# 给搭搭添加自定义角色

搭搭出厂固件不内置角色素材。连接电脑端 MCP 后，你可以直接安装现成的 `role1` 角色包（`.zip`），先装一个内置生成的 `Pocket Bot` 示例角色体验效果，或者让 Agent 帮你制作专属角色。安装完成后，在搭搭屏幕的「角色图鉴」里即可查看、试播和切换。

## 开始前：确认你的获取方式与 Agent 能力

不同方式的准备条件不同，请按实际情况选择：

1. **体验内置示例或安装现成 `.zip` 角色包（任何 Agent 均可）**
   不需要 Agent 具备生图能力，也不需要自己画图。内置的 `Pocket Bot` 由本机 Python 代码直接生成；现成的 `.zip` 角色包经校验后即可传入搭搭储存卡。
2. **只给一句描述或一张参考图，让 Agent 生成全新角色（需 Agent 具备生图能力）**
   普通纯文本/代码 Agent 无法凭空把一张参考图变成多帧动画。如果你想只给文字描述或单张参考图就做出精美的角色动画，**你使用的 Agent 必须内置图像生成能力，或已接入生图 MCP / 生图插件**——由生图工具生成各姿态画帧，再由本机 Python（Pillow）完成透明抠图、锚点对齐、320 × 240 合成预览与打包。
3. **用已画好的 PNG 序列帧打包，或用代码绘制像素/几何角色（无需生图能力）**
   如果你已经准备好各动作的透明 PNG 序列帧，或者希望做一只类似 `Pocket Bot` 的代码绘制（像素风/几何风）角色，任何编程 Agent 都能直接用 Python 完成裁切、编码、预览和安装。

## 直接复制给 Agent 的对话示例

根据你的需求，挑一句复制给已连接搭搭 MCP 的 Agent：

- **想先装个官方示例角色看它动起来（无需生图能力）**：
  > 帮我生成内置的 Pocket Bot 示例角色并装到搭搭上，装好后在搭搭屏幕上打开「角色图鉴」试播一下。

- **已经有下载好的角色 `.zip` 包（无需生图能力）**：
  > 帮我检查一下下载目录里的「小企鹅.zip」角色包是否符合规范，确认没问题后装到我的搭搭上，并在「角色图鉴」里确认能找到它。

- **想让具备生图能力的 Agent 定制新角色（需 Agent 支持生图）**：
  > 请先调用 `desk_read_manual(topic="roles")` 阅读自定义角色指南。帮我制作一只「奶油色小猫」角色（或参考我附上的图片）：平时乖巧眨眼，随打字速度加快从慢走变成开心奔跑，点击屏幕时挥爪，任务完成时跳起来庆祝。请按指南分两步走：先生成角色造型与基础循环动作，用 `desk_check_role` 导出电脑上的 320 × 240 首页合成预览图给我确认构图和右侧数据栏空间；等我确认满意后，再补齐全部动作并安装到搭搭上。

- **已有画好的透明 PNG 序列帧，想打包安装（无需生图能力）**：
  > 请先调用 `desk_read_manual(topic="roles")` 阅读自定义角色指南。我把画好的角色透明 PNG 序列帧和背景图放在了 `~/Desktop/my-pet` 目录，请帮我按规范统一脚底锚点、打包成 role1 ZIP，先用 `desk_check_role` 生成电脑上的 320 × 240 首页预览图给我检查，没问题再装到搭搭上。

## 先体验 Pocket Bot 示例角色

`Pocket Bot` 是内置的技术样例，用来快速体验角色打包、写卡安装和图鉴试播流程（它的 12 个互动复用了少量基础姿态，仅作流程演示，未达到完整角色的丰富度标准）。

- 让 Agent 调用 `desk_create_role_example(destination=...)`，将 `destination` 设为本机已有目录下的一个新 `.zip` 文件绝对路径。
- 工具会在几秒内生成角色包，返回可安装的 `path` 和角色 ID `user-pocket-bot`。该步骤完全在电脑本机完成，无需搭搭在线。
- 如果只想看角色包结构或电脑预览，把生成的 ZIP 留在电脑上即可；想装到搭搭上时，继续执行下方安装步骤。

## 校验、预览与安装到搭搭

1. **电脑端离线校验与合成预览**：
   调用 `desk_check_role(source=..., preview_dir=...)`（均传入本机绝对路径，无需连接搭搭）。
   - 工具会核对必需资源、文件名及大小写、角色 ID、动作数量和命名规则，检查帧与时间轴完整性，并输出 `layout`（首页活动范围与多帧主体稳定性报告）。
   - 传入 `preview_dir` 时，还会在该目录输出叠加了右侧真实数据栏与提醒卡片的 320 × 240 首页动图（`home-idle.gif`、`home-dance-5.gif`）、爆气预览（`home-burst.png`）以及 12 个基础互动总览图（`interactions-sheet.png`）。
   - 若返回 `invalid`，按原因修正；若出现 `layout` 警告，先调整角色站位或锚点。平时也可先用 `desk_list_role_sources(directory=...)` 扫描目录中的候选角色包。
2. **确认目标搭搭在线**：
   调用 `desk_list_devices` 查看已配对的搭搭，再用 `desk_status` 确认连接状态正常。如果电脑配对了多台搭搭，后续工具调用需传入目标设备的 `device_id`。
3. **传输写卡并启用**：
   调用 `desk_install_role(source=...)`，将角色 ZIP 的本机绝对路径填入 `source`。安装器在写卡前会再次校验文件，通过后才加密传输到搭搭储存卡，并由搭搭完成最终校验与启用。
   - 角色 ID 与卡上已有角色不同时，会新增一个角色；
   - 角色 ID 相同时，会更新已有角色（失败时保留原角色不变）。
4. **在角色图鉴中确认与试播**：
   安装返回 `ready` 后，调用 `desk_list_roles` 确认新角色 ID 已在列表中。
   - 你可以在搭搭屏幕上进入「角色图鉴」查看；
   - Agent 也可以调用 `desk_set_view(page="roles")` 直接帮你在屏幕上打开图鉴，并用 `desk_role_preview` 依次试播待机、五档速度和爆气效果（试播结束后会自动返回图鉴并恢复试播前的角色）。

> **常见问题与兼容性提示**：
> - **离线准备与错误排查**：搭搭不在线时，可以先在电脑上把角色包做好并完成 `desk_check_role` 预览。安装报错时，保留本机 ZIP，根据返回回执排查连接、储存卡空间或角色包格式；传输中断结果不明时，先查 `desk_status` 和 `desk_list_roles`。
> - **请勿用普通文件上传工具传角色**：不要用 `desk_upload_files` 直接把普通图片或 ZIP 传到卡上，那样无法完成角色校验与图鉴登记，必须使用 `desk_install_role`。
> - **固件格式要求**：搭搭图鉴只接受完整的 `role1` 角色包（返回 `role1_required` 时需打包为标准 `role1` 格式）。带 `background-hd.565` 高清背景的角色包需要固件支持 `role_hd_background`；若返回 `role_hd_background_not_supported`，请先移除 `background-hd.565` 使用标准 `land.bin` 背景安装。从储存卡备份恢复角色时，可将备份的 `roles/<角色 ID>/<版本>` 目录作为 `source` 传入，恢复后会沿用备份中的完成动作配置。

## 完整角色交付标准

一个完整的自定义角色需要能在图鉴中清晰识别、在首页与右侧数据栏和谐共处，并能自然响应 Token 速度换档与日常互动事件。系统决定何时触发动作，每个角色用自己的姿态和节奏表达动作含义：

- **图鉴与场景构图**：提供稳定的角色 ID、图鉴显示名称、透明角色画帧和可独立复用的背景。在 320 × 240 画面中必须给右侧读数、底部趋势折线和顶部状态栏留出充足空间；各动作切换时角色站位须保持连贯。
- **五档速度动作（`dance_1` ～ `dance_5`）**：从慢到快提供 5 个可独立循环的动作序列。相邻档位应有明显的速度或幅度递进，且每个循环首尾衔接顺滑。
- **独立爆气特效（`dance_burst`）**：提供可叠加在角色后方的独立高光特效帧。触发和结束时，当前档位的角色动作保持连续。
- **待机表情（`idle`）**：提供 3～9 张可辨识的待机帧，首帧作为默认表情。待机表情与互动动作分别验收，画面允许按需复用。
- **基础互动动作（必选 12 项）**：逐一制作并验收下表中的 12 个基础互动动作，确保动作含义一眼可辨（其余 18 个扩展动作可按需补充）：

| 用途分类 | 必选基础互动动作（固定动作 ID） |
| --- | --- |
| 日常状态 | 轻呼吸 `idle_breathe`、眨眼 `idle_blink`、醒来 `wake`、专注 `focus` |
| 等待与引导 | 举手 `raise_hand`、等回复 `wait_reply`、请求确认 `show_approval`、指向列表 `point_list` |
| 结果与互动 | 小庆祝 `celebrate_small`、受惊 `startled`、被触碰 `touched`、断开连接 `disconnected` |

## 给制作角色的 Agent（制作与打包规范）

当用户要求制作自定义角色时，请遵循**「先预览确认、再全量制作」**的两阶段流程：
1. **第一阶段（造型与排版预览）**：从用户的描述或参考图出发，先制作角色主造型、背景和一段最具代表性的循环动作，缩放到 320 × 240 检查辨识度与右侧数据栏留白，打包后用 `desk_check_role(source=..., preview_dir=...)` 生成 `home-idle.gif` 等合成预览图拿给用户确认。如果用户只要求先看电脑预览，交付到这一步即可。
2. **第二阶段（全量动作与上机验收）**：用户确认预览满意后，补齐五档速度、待机、爆气和全部 12 个基础互动动作，再次通过 `desk_check_role` 校验无误后调用 `desk_install_role` 安装到搭搭上。

### 代码起点与打包方法

示例源码 `deskpet_platform.role_example` 随 Python 包一起安装，可直接复制到工作目录作为打包脚本起点：
- 修改副本中的 `IDENTITY`（例如 `user-cream-cat`）、`NAME`（图鉴显示名）以及 `example_files()` 中的素材生成逻辑；
- 将示例中用代码绘制的 `pose()` 替换为用 `Pillow` 读取并处理好的透明 PNG 序列帧，直接复用示例里的 `motion_cel`、`motion_file` 和 `interaction_files` 完成二进制编码；
- 保留示例的打包与校验入口，使用同一个 Python 环境导入副本并调用 `create_role_example`，输出到新的 `.zip` 路径。

### 画布尺寸、坐标与防抖规范

| 素材项 | 制作约定与硬性规范 |
| --- | --- |
| **角色名与 ID** | 图鉴名写入 `manifest.json` 并实际绘制到图鉴行（`row.565`）中。角色 ID 必须以 `user-` 开头，后接小写英文字母或数字，后续可用小写字母、数字和连字符，含前缀总长不超过 48 字符。 |
| **首页活动范围与层级** | 320 × 240 首页中，右侧数据栏与提醒卡片从 `x = 176` 开始，左上菜单与顶栏位于 `y < 24`，底部趋势折线与状态栏位于 `y >= 192`，且界面文字与数据始终绘制在角色图层**上方**。因此，非爆气帧的可见像素必须留在 `x < 176` 左侧区域（建议角色主体与常规手脚控制在 `x: 8..168, y: 28..190`），避免画面拥挤或被右侧数据栏遮挡。 |
| **多帧主体稳定性（防抖）** | 所有待机、五档速度和互动帧必须共享**同一个脚底或地面支撑锚点**。手脚伸展、挥爪和跳跃允许自然改变外框，但**严禁**对单帧透明边界单独调用 `getbbox()` 裁切后再居中或不等比缩放——否则会导致角色躯干在帧与帧之间剧烈抖动、漂移。 |
| **待机、速度与爆气** | 画布尺寸统一为 `184 × 192` 透明帧（写入 `motion.bin`）。按顺序依次存放：5 个由慢到快的速度动作序列 → 3～9 张待机帧（首帧为默认表情）→ 独立爆气特效帧，总帧数不超过 128 帧。爆气特效在屏幕上会叠加绘制在角色后方。 |
| **互动动作** | 画布尺寸统一为 `176 × 160` 透明帧（写入 `pet-v2/frames.bin` 与 `pet-v2/timeline-v2.bin`），与运动帧使用**完全相同的屏幕角色坐标**。标准做法是先在 `184 × 192` 运动画布上按统一锚点绘制，再固定裁取 `(4, 25, 180, 185)` 区域（对应画布锚点 `(88, 159)` 落在屏幕 `(92, 184)`），确保待机与互动切换时角色分毫不差、不会位移。按上表固定顺序与 ID 编排全部 12 个基础互动动作。 |
| **背景（`land.bin`）** | 屏幕实际显示中间的 `320 × 240`。`land.bin` 编码画布尺寸为 `336 × 240`，左右各多留 8 像素（可用相邻边缘颜色补齐）。 |
| **图鉴行（`row.565`）** | 尺寸为 `320 × 68`（小端 RGB565），左侧放角色头像，中间绘制清晰可读的角色名（使用系统或随包中文字体），最右侧留出空白供固件绘制「当前选中」标记。 |

### 交付前必做验收

每次打包完成后，必须运行 `desk_check_role(source=..., preview_dir=...)` 同时完成静态规范校验与 320 × 240 视觉验收：
1. 确认返回结果中 `status` 为 `"valid"`，且 `layout.status` 为 `"ok"`（无右侧越界、层间坐标错位或帧间主体跳变警告）；
2. 亲自打开 `preview_dir` 下生成的 `home-idle.gif`、`home-dance-5.gif`、`home-burst.png` 与 `interactions-sheet.png`，目视确认右侧数据栏清晰无遮挡、角色脚底站位稳固、动作连贯自然；
3. 当用户要求装上搭搭时，继续调用 `desk_install_role` 完成写卡安装，并在搭搭实屏上核对图鉴显示、默认待机、五档变速、爆气和点击互动效果。
