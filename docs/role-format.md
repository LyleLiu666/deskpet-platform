# 角色包与动作接口

如果想从参考图制作角色或安装可运行样例，先看[自定义角色指南](../src/deskpet_platform/manuals/roles.md)。

所有角色使用同一套 MCP 接口：`desk_install_role` 安装并启用，`desk_list_roles` 和 `desk_select_role` 查询与切换，`desk_list_actions` 查询当前角色的动作，`desk_set_role_base` 设置持续动作，`desk_play_action` 临时播放动作并在结束后返回持续动作。固件不内置角色素材。安装过程先把一个完整版本写入储存卡，校验后才更新启用记录；失败时保留原角色。

## role1 ZIP

`desk_install_role` 可直接安装原桌面屏的 role1 ZIP。ZIP 必须恰好包含 `manifest.json`、`kind`、`row.565`、`land.bin`、`motion.bin`、`pet-v2/frames.bin` 和 `pet-v2/timeline-v2.bin` 七个文件，按所列路径和大小写存放。`manifest.json` 中的 `id` 作为角色标识，`row.565` 供图鉴使用。

解压后的目录也能安装。目录名使用清单 ID，安装时会把 `motion.bin` 暂存为卡上使用的 `motion-v2.bin`。从储存卡备份时，可直接提交 `roles/<角色 ID>/<版本>` 对应的版本目录，角色 ID 从清单读取。目录可附带 `actions.txt`、`events.json`、`event.txt` 和 `background.565`。完成动作优先取 `events.json`，其次读取固件保存的 `event.txt`。其中 `-\n` 表示只发文字提醒。安装会让固件重新生成动作和事件配置。

素材项目可单独更新已安装角色的图鉴行。将 320 × 68 小端 RGB565 图鉴行传到 `desk/role-catalog/<角色标识>.565`。缺少此文件或长度不符时，图鉴使用角色包的 `row.565`。新图鉴行使用白底，头像填满左侧区域，角色名和储存卡标识排在右侧，最右边留给固件绘制选中标记。

保留原包的互动动作顺序。DNC1 v2 动作按原帧时长播放，分别通过 `idle`、`dance_1` 到 `dance_5` 和 `dance_burst` 调用。校准后点击角色区可本地播放 `touched`。原包默认用 `deliver_result` 响应会话完成，只有基础互动集的包使用 `celebrate_small`。

带 DNC1 v3 动作文件的 ZIP 在原有动作后增加 `glide_1` 到 `glide_5`。自动模式下持续有速度时，设备按角色包的计时和安全帧在跑动与滑行间切换，换档时保留当前阶段。停止、切换角色或退出自动模式会重置轮换。滑行也可以通过 MCP 单独播放或设为持续动作。已有 DNC1 v2 ZIP 仍可安装。

## 角色目录

角色目录名称作为角色标识，只能使用英文字母、数字、下划线和连字符，长度不超过 48。目录内需要：

```text
<角色标识>/
  pet-v2/
    frames.bin
    timeline-v2.bin     # 或 timeline-v3.bin
    manifest.json       # 原有角色可用其中的 actions[].id
  actions.txt           # 可选：每行一个动作名；优先于 manifest
  events.json           # 可选：将会话完成事件映射到已有动作
  background.565        # 可选：320 × 240、小端 RGB565
```

一个角色最多包含 100 个文件，单文件不超过 128 MiB，总素材不超过 512 MiB。动作名按时间轴顺序排列，必须唯一，使用小写英文字母、数字和下划线，以字母开头，最长 32 字符。动作数为 1–48，所有名称与换行的总长度不超过 600 字节。动作名称由角色包的 `actions.txt` 或 `manifest.json` 声明，底座不会根据动作数量猜测名称。

安装器也能读取参考项目的 DNC1 双人舞目录，在电脑上转换成上述格式再上传。它保留独立的五档舞蹈及每一帧的时长；爆气效果合成为独立动作。转换不修改来源目录。原有 `land.bin` 会在可识别时转换为背景图。

恢复参考固件上的传统角色时，保留备份的 `roles/<角色 ID>/<版本>` 目录结构，将版本目录传给安装器。传统角色没有 role1 清单，安装器从父目录读取角色 ID。

设备按时间检查是否需要绘制下一帧，相同帧不会重复刷新。先用帧数除以动作时长（秒）计算素材帧率，再用 `desk_render_metrics` 的 `displayed_fps` 核对实机写屏帧率。角色的待机和低档可以使用较长的单帧时长。

`events.json` 可以写 `{"turn_finished": "动作名"}`，使 Codex 会话结束时播放该角色已有动作。值为 `null` 时只显示文字提醒。传统目录省略该文件时也只显示文字提醒。映射必须指向该角色实际提供的动作。

### 旧角色偏好

移植候选版的桌宠主页可以从 SD 卡上的 `desk/role-aliases.txt` 恢复已改名的角色。素材项目随卡提供此文件。每行是旧标识、一个 Tab 字符、目标 role1 标识和换行。支持 LF 和 CRLF，文件上限为 6,336 字节。两个标识均遵守上面的角色目录命名规则。

已保存的标识若仍在可选列表，设备优先尝试加载该角色。别名只匹配已安装且具备互动的 role1，按标识直接查找。若别名缺失、目标不可用、文件损坏或同一旧标识有多个条目，设备继续按正常顺序查找可播放的角色，保留原偏好以便日后恢复。

通过别名成功加载时，电脑端显示当前角色会在重启后恢复。临时回退到其他角色时，电脑端显示该角色尚未保存为偏好。

## 动作文件

整数均为小端。帧文件头为 `<4sHHHHII>`：魔数 `PET1`、版本 1、宽、高、动作数、帧数和帧数据 CRC32。宽不超过 320，高不超过 240，单帧像素数不超过 64,768；帧数为 1–1024。

每帧包含 256 项调色板及逐像素索引。每个调色板项为一个 RGB565 值和一个 8 位透明度，共 768 字节；随后为 `宽 × 高` 字节索引。设备只缓存当前帧。

有序时间轴头为 `<4sHHIII>`：魔数 `PTL1`、版本 2、动作数、记录区字节数、记录区 CRC32 和所绑定帧数据的 CRC32。每个动作记录 80 字节：先是 `<BHBHBBIhh>`，依次为动作编号、首帧、帧数、动作时长毫秒、循环标记、回退动作编号、安全帧位图、锚点 X/Y；然后是 32 个 uint16 帧索引，仅前“帧数”项有效。帧数为 1–32，时长为 100–6000 毫秒，帧索引和锚点必须在帧文件范围内。设备将帧均匀分配在动作时长内。

逐帧计时的时间轴使用 `timeline-v3.bin`，头结构不变，版本为 3。每个动作记录 276 字节：`<BHBHBBQhh>` 中安全帧位图扩大为 64 位，随后是 64 个 uint16 帧索引和 64 个 uint16 帧时长（毫秒），各取前“帧数”项。帧数为 1–64，每帧时长必须大于零，合计等于动作时长。存在版本 3 文件时优先校验它，损坏时不会悄悄退回旧版本。

DNC1 v3 保留 `<4s6HI>` 头，将速度片段数设为 10。紧随其后的十个 `<HH>` 片段依次为五档跑动和五档滑行，各给出连续的起始帧和帧数。后面的 `<HH5Q>` 给出跑动和滑行时长（各 1–60000 毫秒），以及五档跑动的安全帧位图。每个跑动片段最多 64 帧。位图至少有一位，且只能引用相应跑动片段的帧。随后是逐帧 `<IIIHH>` 记录，字段为文件偏移、长度、CRC32、毫秒和保留位。待机与爆气帧排在滑行帧后，总帧数仍以 128 为上限。v2 和 v3 安装到卡上时均使用 `motion-v2.bin` 文件名。

## 验证边界

`desk_check_role(source=...)` 可以在电脑端单独检查文件完整性、路径、角色及动作名称。安装器对本次暂存的文件执行相同检查，再核对目标设备支持的格式。完整显示固件只接受 role1，遇到传统角色目录会在写卡前返回 `role1_required`。设备再次检查帧及时间轴，确认后才启用。相同版本的文件不可被不同内容覆盖。传输使用设备配对密钥加密，并在卡上校验后替换。卡掉电和物理拔插恢复仍需实板验收。
