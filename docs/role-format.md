# 角色包格式与动作接口规范

本文档定义搭搭（DeskPet）角色包的文件组成、二进制动作格式与校验边界。如果你想快速体验内置示例角色、安装现成角色包或让 Agent 制作自定义角色，请先阅读[自定义角色指南](../src/deskpet_platform/manuals/roles.md)。

所有角色共用同一套 MCP 接口：
- `desk_check_role`：电脑端离线检查角色包结构、首页活动范围与多帧稳定性，并可导出 320 × 240 首页合成预览图；
- `desk_install_role`：校验通过后将完整角色版本加密写入搭搭储存卡，由搭搭二次校验并启用（失败时保留原角色不变）；
- `desk_list_roles` / `desk_select_role`：查询储存卡中已安装的角色并切换；
- `desk_list_actions` / `desk_set_role_base` / `desk_play_action`：查询当前角色支持的动作、设置持续基础动作、临时播放互动动作（播完自动回到持续动作）。

## 1. 标准 `role1` ZIP 角色包

搭搭图鉴使用标准的 `role1` ZIP 角色包。`desk_install_role` 可直接安装 `.zip` 文件或解压后的同结构目录。ZIP 包内必须按以下路径和精确大小写包含 7 个必需文件（可选附带 `background-hd.565`）：

| 包内路径 | 是否必需 | 规格与用途 |
| --- | --- | --- |
| `manifest.json` | 必需 | UTF-8 JSON，包含 `"version": 1`、角色标识 `"id"`（如 `"user-pocket-bot"`）和图鉴显示名 `"name"`。 |
| `kind` | 必需 | 固定文本 `"role1\n"`，声明包格式版本。 |
| `row.565` | 必需 | `320 × 68` 小端 RGB565 图鉴行图像（恰好 43,520 字节），供「角色图鉴」列表展示。 |
| `land.bin` | 必需 | `336 × 240` 索引色场景背景（屏幕实际取居中 `320 × 240`，左右各留 8 像素冗余）。 |
| `motion.bin` | 必需 | `DNC1` v2 或 v3 格式的运动帧文件（包含五档速度、可选五档滑行、待机表情与独立爆气特效；安装到卡上时暂存为 `motion-v2.bin`）。 |
| `pet-v2/frames.bin` | 必需 | `PET1` 格式的互动动作透明帧文件（标准尺寸 `176 × 160`）。 |
| `pet-v2/timeline-v2.bin` | 必需 | `PTL1` v2（或 `timeline-v3.bin`）时间轴文件，定义各互动动作的帧序列、时长与锚点。 |
| `background-hd.565` | 可选 | 预先按屏幕构图裁切的 `480 × 320` 小端 RGB565 高清背景（恰好 307,200 字节）。需固件声明 `role_hd_background` 能力（工作台使用该背景并叠加暗角，图鉴预览仍使用 `land.bin`；不支持的设备在传输前即会拒绝并返回 `role_hd_background_not_supported`）。 |

### 解压目录、卡上备份恢复与图鉴行覆盖

- **解压目录与备份恢复**：解压后的 `role1` 目录也可直接作为 `source` 安装。从储存卡备份恢复角色时，可直接传入 `roles/<角色 ID>/<版本>` 对应的版本目录（角色 ID 从清单读取）。目录可附带 `actions.txt`、`events.json`、`event.txt` 和 `background.565`；会话完成触发的动作优先取 `events.json`，其次读取固件保存的 `event.txt`（内容为 `-\n` 时表示仅显示文字提醒）。
- **单独更新图鉴行**：如需单独更新已安装角色的图鉴显示行，可将 `320 × 68` 小端 RGB565 文件上传至储存卡的 `desk/role-catalog/<角色标识>.565`（白底，左侧放头像，右侧排角色名与储存卡标记，最右端留给固件绘制选中标记）。若无此文件或字节长度不符，图鉴默认使用角色包内的 `row.565`。
- **动作调用与五档滑行（`DNC1` v3）**：
  - 运动帧中的待机、五档速度与爆气分别通过动作名 `idle`、`dance_1` ～ `dance_5` 和 `dance_burst` 调用；完成触屏校准后，轻触屏幕角色区会本地触发 `touched`。
  - 含完整 30 个互动动作的角色包默认用 `deliver_result` 响应会话完成；仅含 12 个基础互动动作的角色包默认使用 `celebrate_small`。
  - 使用 `DNC1` v3 运动文件的角色包在原有动作之后新增 `glide_1` ～ `glide_5` 五档滑行。在自动换档模式下持续有 Token 速度时，搭搭会按包内设定的计时与安全帧在「跑动」与「滑行」间平滑切换，换档时保留当前阶段（停止、切换角色或退出自动模式会重置轮换）。滑行动作也可通过 MCP 单独播放或设为持续动作。

## 2. 传统角色目录与兼容转换

对于旧版/参考固件使用的传统 `PET1` 角色目录，目录名即作为角色标识（仅限英文字母、数字、下划线和连字符，长度不超过 48 字符），目录结构如下：

```text
<角色标识>/
  pet-v2/
    frames.bin
    timeline-v2.bin     # 或 timeline-v3.bin
    manifest.json       # 可选：声明 actions[].id
  actions.txt           # 可选：每行一个动作名（优先级高于 manifest.json）
  events.json           # 可选：如 {"turn_finished": "动作名"}，设为 null 则仅显示文字提醒
  background.565        # 可选：320 × 240 小端 RGB565
  background-hd.565     # 可选：480 × 320 小端 RGB565（需设备支持）
```

- **资源与命名上限**：单个角色最多包含 100 个文件，单文件不超过 128 MiB，总大小不超过 512 MiB。动作名按时间轴顺序排列且必须唯一，使用小写英文字母、数字和下划线（以字母开头，最长 32 字符）；动作数量为 1～48 个，所有动作名称与换行符总长不超过 600 字节。动作名称必须由 `actions.txt` 或 `manifest.json` 明确声明，电脑端不会按动作数量猜测名称。
- **DNC1 目录转换与传统备份恢复**：安装器支持读取展开的 `DNC1` 动作目录并在电脑端自动转换为上述结构后上传（保留独立五档动作与逐帧时长，将爆气合成为独立动作，可识别的 `land.bin` 自动转为背景图，且不修改源目录）。从旧版/参考固件储存卡恢复传统角色备份时，请保留 `roles/<角色 ID>/<版本>` 目录层级并将版本目录传给安装器，以便从父目录提取角色 ID。
- **角色改名别名映射（`desk/role-aliases.txt`）**：固件支持从储存卡 `desk/role-aliases.txt` 读取角色改名映射，以便在角色 ID 更新后平滑恢复用户保存的偏好。文件每行为 `旧标识<Tab>目标role1标识`（支持 LF / CRLF，上限 6,336 字节）。当原角色标识不存在时，设备按别名查找已安装的 `role1` 角色；若别名缺失或目标不可用，则按正常顺序回退到首个可播放角色，并保留原偏好记录供日后恢复。

## 3. 二进制动作文件结构

所有多字节整数均采用**小端序（Little-Endian）**。设备按帧时长判断是否需要绘制下一帧，连续相同帧不会重复刷屏（可用总帧数除以动作秒数计算素材帧率，并通过 `desk_render_metrics` 的 `displayed_fps` 核对实机写屏帧率）。

### `PET1` 互动帧文件（`pet-v2/frames.bin`）

- **文件头**：`struct.pack("<4sHHHHII", b"PET1", 1, width, height, action_count, frame_count, frames_crc32)`
  - 宽 `width <= 320`，高 `height <= 240`，单帧像素数 `width * height <= 64,768`，总帧数 `1 <= frame_count <= 1024`。
- **单帧数据**：每帧依次包含 256 项调色板（每项为 2 字节小端 RGB565 + 1 字节 Alpha 透明度，共 768 字节）及 `width × height` 字节的像素调色板索引。设备在内存中仅缓存当前帧。

### `PTL1` 时间轴文件（`timeline-v2.bin` / `timeline-v3.bin`）

- **文件头**：`struct.pack("<4sHHIII", b"PTL1", version, action_count, records_bytes, records_crc32, frames_crc32)`
- **版本 2（均匀帧时长，`timeline-v2.bin`）**：
  - 每条动作记录固定 **80 字节**：头部 `<BHBHBBIhh>` 依次为动作编号、首帧索引、帧数（`1..32`）、动作总时长（`100..6000` 毫秒）、循环标记、回退动作编号、32 位安全帧位图、锚点 X/Y；随后是 32 个 `uint16` 帧索引（仅前「帧数」项有效）。设备将各帧均匀分布在动作总时长内。
- **版本 3（逐帧独立时长，`timeline-v3.bin`）**：
  - 每条动作记录固定 **276 字节**：头部 `<BHBHBBQhh>` 将安全帧位图扩展为 64 位；随后是 64 个 `uint16` 帧索引和 64 个 `uint16` 单帧时长（毫秒），各取前「帧数」项（帧数 `1..64`，每帧时长必须 `> 0` 且总和等于动作总时长）。
  - 目录中存在 `timeline-v3.bin` 时优先校验并使用版本 3；若版本 3 文件损坏会直接报错，不会静默回退到旧版本。

### `DNC1` 运动帧文件（`motion.bin` / `motion-v2.bin`）

- **文件头**：`struct.pack("<4s6HI", b"DNC1", version, width, height, clip_count, frame_count, burst_count, total_bytes)`（标准画布 `184 × 192`，总帧数上限 `128`）。
- **版本 2（五档速度 + 待机 + 爆气）**：`clip_count = 5`，紧随文件头后为 5 个 `<HH>` 片段（依次给出五档速度的起始帧与帧数），随后是待机帧与 `burst_count` 张爆气帧。
- **版本 3（五档跑动 + 五档滑行 + 待机 + 爆气）**：`clip_count = 10`，紧随文件头后为 10 个 `<HH>` 片段（前 5 个为五档跑动，每个片段最多 64 帧；后 5 个为五档滑行），再跟 `<HH5Q>`（跑动持续毫秒数、滑行持续毫秒数，各 `1..60000` 毫秒；以及五档跑动的 64 位安全帧位图，每位图至少置 1 位且仅能引用对应跑动片段内的帧）。待机与爆气帧排在滑行帧之后。
- **帧表与压缩行数据**：片段描述之后是逐帧 `<IIIHH>` 索引表（文件偏移、字节长度、帧数据 CRC32、单帧时长毫秒、保留位 0），随后紧跟各帧的行程编码（RLE）调色板图像数据。

## 4. 校验与安全边界

1. **电脑端预检（`desk_check_role`）**：离线核对所有必需文件、路径大小写、CRC32、角色及动作命名，并对 `role1` 包自动分析 320 × 240 首页活动范围（右栏数据自 `x = 176` 起、顶栏 `y < 24`、底栏 `y >= 192`）与多帧主体脚底锚点稳定性，可选渲染带真实首页右栏叠层的合成预览图。
2. **传输前能力匹配（`desk_install_role`）**：安装器对本次暂存的文件重新执行完整格式校验，并核对目标搭搭声明的固件能力（标准搭搭固件要求 `role1` 格式，遇到传统 `PET1` 目录会在写卡前直接返回 `role1_required`，避免无效写卡）。
3. **加密传输与板端原子启用**：文件通过配对会话密钥加密传输，写入储存卡独立版本目录；同一版本哈希的文件不可被不同内容覆盖。所有文件写完后，搭搭在板端再次校验帧与时间轴，全部通过后才原子切换启用记录；中途任何一步失败均保留原角色。
